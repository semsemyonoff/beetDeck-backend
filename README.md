# beetDeck backend

Flask + gunicorn API and [beets](https://beets.io/) integration for beetDeck — the
**backend part** of the product. It exposes the `/api` endpoints and serves the
pre-built SPA on `:5000`. There is no shared code or filesystem with the
frontend; the React SPA lives in a **separate repository** and talks to this
backend purely over HTTP.

The full product overview, install, configuration (env vars, volumes, beets
plugins), and release process live in the separate **`beetDeck/deploy`**
repository — the **entry point**, which pins this backend and the frontend as
submodules and builds the single published image (`semsemyonoff/beetdeck`). This
repo is source for the backend only.

## Requirements

- Python 3.10+ (the production image uses 3.14)
- ffmpeg (audio fingerprinting and BPM computation)
- beets — pinned to an exact release tarball in `pyproject.toml`; that pin is the
  single source of truth for the version

## Architecture

- **Flask + gunicorn** (1 worker, 4 threads). A single worker is required because
  in-memory state (identification tasks, cover previews, scan progress) is shared
  across request threads — see *Architecture constraints* in `CLAUDE.md`. Routes
  are organized as Flask Blueprints under `beetdeck/routes/`.
- **beets integration**: uses the beets Python API directly (not the CLI) for
  identification, genre lookup, cover art, and lyrics. The CLI is only used for
  `beet import` (rescan) and `beet update` (prune stale entries). Genres are
  stored as native list fields; library paths are stored relative to the database
  root and resolved at runtime.
- **SPA serving**: in production the frontend's build is dropped into
  `beetdeck/static/dist/` and served by Flask — the Vite manifest is read at request
  time to inject the hashed JS/CSS into `beetdeck/templates/index.html`.

The app reads `BEETS_LIBRARY_DB`, `BEETS_IMPORT_DIR`, `BEETS_LIBRARY_ROOT`, and
`BEETS_COVER_CACHE_DIR` from the environment; the `beet` CLI reads `BEETSDIR`.
Defaults are tabulated in `CLAUDE.md` → *Configuration*.

## Local development

Dependencies are declared in `pyproject.toml` (runtime under `[project]`, tooling
under the `dev` extra). Install them into a virtualenv with an editable install:

```bash
python -m venv .venv && . .venv/bin/activate
pip install -e ".[dev]"

# Run the Flask dev server on :5000
make run

# Run tests
make test

# Lint / format
make lint
make fmt

# Coverage report
make coverage
```

The frontend SPA lives in its own repository and is served by Flask in
production from `beetdeck/static/dist/`. To exercise the full UI locally, run the
frontend's Vite dev server from its repository (HMR) and point it at this
backend's API. Producing the production image (which builds the SPA and bakes it
in) is the job of the `beetDeck/deploy` repository; see its README.

## API reference

The API is documented from code via an OpenAPI 3.x spec generated by
[spectree](https://github.com/0b01001001/spectree) (pydantic v2). It is the
single source of truth — there is no hand-maintained endpoint table here.

- **Interactive docs (Scalar):** `GET /apidoc/scalar/` (bare `/apidoc/scalar` redirects to it)
- **OpenAPI spec (JSON):** `GET /apidoc/openapi.json`

Request models live in `beetdeck/schemas/` (one module per blueprint plus a shared
`common.py`); the `SpecTree` singleton lives in `beetdeck/api.py`.

## MCP server

`beetdeck_mcp/` exposes the library to an MCP client (streamable-http) — album
browsing, MusicBrainz identification, cover art, lyrics, genres, tag edits, plus
library rescans, per-track BPM computation, the album ignore flag and a `GET`-only
`/api/` escape hatch. It is a **separate process** from Flask, shipped in the same
install and image, and it talks to this backend over HTTP. Every mutating
capability is two-phase: a `preview_*` tool returns a diff plus a single-use token,
and `apply_change` is the only tool that writes. Design notes and the per-kind
freshness guarantees are in `CLAUDE.md` → *MCP server*.

| env | default | notes |
|---|---|---|
| `BEETDECK_API_URL` | `http://backend:5000` | this backend's base URL |
| `BEETDECK_MCP_TOKEN` | — | comma-separated bearer tokens; **empty ⇒ refuses to start** |
| `MUSICBRAINZ_USER_AGENT` | — | `app/version (contact)`; **empty ⇒ refuses to start** |
| `BEETDECK_MCP_READONLY` | `0` | disables `apply_change` only — previews still run, and `rescan_library` / `compute_bpm` / `toggle_album_ignored` still write |
| `BEETDECK_MCP_HOST` / `_PORT` | `0.0.0.0` / `5100` | bind address of this process |
| `BEETDECK_MCP_ALLOWED_HOSTS` | — | DNS-rebinding allowlist; needed behind a hostname. **Empty ⇒ the check is off entirely**, not narrowed to localhost |

With the backend already running on `:5000`:

```bash
export BEETDECK_API_URL=http://127.0.0.1:5000
export BEETDECK_MCP_TOKEN=$(python -c 'import secrets; print(secrets.token_urlsafe(32))')
export MUSICBRAINZ_USER_AGENT='beetdeck-dev/0.0 (you@example.com)'
python -m beetdeck_mcp
```

The MCP endpoint is `POST /mcp` on that port, authenticated with
`Authorization: Bearer <token>`; `GET /health` is unauthenticated and reports
`{"status": "ok", "readonly": …}`. Point a client at it, e.g. for Claude Code:

```bash
claude mcp add --transport http beetdeck http://127.0.0.1:5100/mcp \
  --header "Authorization: Bearer $BEETDECK_MCP_TOKEN"
```

There is no reloader — restart the process after editing `beetdeck_mcp/`.
